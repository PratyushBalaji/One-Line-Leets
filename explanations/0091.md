# Solution 91 - Decode Ways

## Solution :

```python
def numDecodings(self, s):
    return sum(reduce(lambda x, n: (lambda t: [(t if n == 1 else 0), (t if n == 2 else 0), (t if 3 <= n <= 9 else 0) + x[0] + (x[1] if 0 <= n <= 6 else 0)])(sum(x)), map(int, list(s)), [0,0,1]))
```
Runtime : $O(n)$

Memory : $O(n)$ (*but only due to using `map()` + `list()` to ingest digits, can be written to be $O(1)$ imperatively*)

## Explanation :

We need to count how many ways a string of digits can be split into numbers from `1` to `26`, corresponding to letters `A` to `Z`. A `0` cannot be decoded by itself, but it can be part of `10` or `20`. Similarly, `06` is not a valid code, even though `6` is.

Rather than constructing every possible decoded string, if we notice that each letter can be at most 2 digits long (1-26), we can solve the problem dynamically! With each prefix of the string, we determine how many ways that prefix can be decoded, and ingesting a new digit means the new number of ways is just a function of the previous number of ways and at most one preceding digit!

So we keep track of how many ways we can decode each prefix. As we read the next digit, we can either decode it as a new letter (`1 <- 1 = 1 1 = A A`, or combine it with the previous digit to form a two-digit code (`1 <- 1 = 11 = K`).

### Choosing the DP state

For each prefix, I split its valid decodings into three groups :

| Group | Decodings whose last letter is :  | Why keep it separate? |
|---|---|---|
| `0` | `A` (ingested number is `1`)    | That `1` can combine with the next digit to form `10` through `19`. |
| `1` | `B` (ingested number is `2`)| That `2` can combine with the next digit to form `20` through `26`. |
| `2` | Any letter from `C-Z` (ingested number is `0-9`) | Its code cannot be extended by another digit to form a valid code. |

These are counts of complete decodings of the current prefix. The first two groups also tell us which decodings can have their final single-digit code replaced with a two-digit code on the next iteration.

For example, `12` has two decodings: `AB` and `L`. Its state is `[0,1,1]` : one decoding ends in `B`, and one ends in another letter. Although the raw prefix ends in `2`, only `AB` has a final single-digit `2` available to combine with another digit. The `2` in `L` has already been used as part of `12`.

This is why just remembering the final digit is not enough for this particular state representation. We need the counts of decodings in each group.

### Building the full table

Let's call the table `dp`. Row `i` describes the first `i` digits, so we need `len(s)+1` rows, each with three columns.

```python
dp = [[0]*3 for _ in range(len(s)+1)]
dp[0][2] = 1
```

The initial state `[0,0,1]` represents one way to decode an empty prefix : choose nothing. It doesn't literally end in a letter from `C` to `Z`; we place this starting count in column `2` so it contributes to the total as there is `1` way to decode an empty string, but no preceding `A`s or `B`s to use.

Suppose the current digit is `n` and the previous row is `dp[i]`. First, count all the valid decodings of the previous prefix :

```python
total = sum(dp[i])
```

If `n` is a valid single-digit code, we can append its letter to every one of these decodings without any merging :

```python
if n == 1:
    dp[i+1][0] += total #
if n == 2:
    dp[i+1][1] += total
if 3 <= n <= 9:
    dp[i+1][2] += total
```

Notice `0` will never trigger any of these conditions, it doesn't get a single-digit transition as a standalone `0` doesn't represent a letter. This prevents zeroes and leading zeroes from producing valid decodings. These if statements are also mutually exclusive by their conditions on `n`, so only one ever runs.

Next, count the ways to make a two-digit code. Any decoding ending in `A` has a final `1` that can combine with the new digit, giving a code from `10` to `19`. All of these resulting letters belong in column `2` :

```python
dp[i+1][2] += dp[i][0]
```
We do not need a condition here as a single digit can only be `0-9` and all of these are acceptable to combine with `A`.

Similarly, a decoding ending in `B` can combine its final `2` with the new digit to get letters `20-26`, but only when that digit is between `0` and `6` :

```python
if 0 <= n <= 6:
    dp[i+1][2] += dp[i][1]
```

We are counting alternative decodings here when ingesting a new digit, not changing the previous row. For example, when extending `12` to `123`, `AB` can become `ABC` by appending `C`, or `AW` by replacing the final `2` with `23`. Meanwhile, `L` can become `LC`. These are three different decodings.

Putting everything together gives the original program:

```python
def numDecodings(self, s):
    # dp cols : end w/ a | end w/ b | end w/ c-z
    dp = [[0]*3 for _ in range(len(s)+1)]
    dp[0][2] = 1

    for i in range(len(s)):
        n = int(s[i])
        total = sum(dp[i])
        if n == 1:
            dp[i+1][0] += total
        if n == 2:
            dp[i+1][1] += total
        if 3 <= n <= 9:
            dp[i+1][2] += total

        dp[i+1][2] += dp[i][0]
        if 0 <= n <= 6:
            dp[i+1][2] += dp[i][1]

    return sum(dp[-1])
```

We sum the final row because a valid decoding can end in any of the three groups.

### Stepping through an example

For `s = "226"`, the table evolves like so:

| Prefix | Ends in `A` | Ends in `B` | Ends in `C`–`Z` | Total |
|---|---|---|---|---|
| Empty | 0 | 0 | 1 | 1 |
| `2` | 0 | 1 | 0 | 1 |
| `22` | 0 | 1 | 1 | 2 |
| `226` | 0 | 0 | 3 | 3 |

After `22`, the two decodings are `BB` and `V`. Appending `6` gives `BBF` and `VF`. The decoding ending in `B` also allows `26` to become `Z`, giving `BZ`. So the answer is `3`.

Zeroes follow the same rules without special early returns. `10` becomes `[0,0,1]`, since `1` and `0` combine into `J`. But `30` becomes `[0,0,0]`: `0` cannot stand alone, and `30` is outside the mapping. Once the state is all zeroes, later digits cannot create a valid decoding from it.

### Keeping only two arrays

The table works, but look at what each iteration actually reads: only `dp[i]`. Once we have computed `dp[i+1]`, none of the older rows are needed again!

So instead of keeping the whole table, we can use a current array and a next array:

```python
current = [0,0,1]
for c in s:
    n = int(c)
    total = sum(current)
    nextState = [0,0,0]

    if n == 1:
        nextState[0] += total
    if n == 2:
        nextState[1] += total
    if 3 <= n <= 9:
        nextState[2] += total

    nextState[2] += current[0]
    if 0 <= n <= 6:
        nextState[2] += current[1]

    current = nextState

return sum(current)
```

This keeps a constant number of counts instead of a row for every character, giving us $O(1)$ memory instead of $O(n)$!

### Replacing the current state directly

The next array is only used to replace the current array at the end of the iteration. We can construct the entire next state in one expression and assign it directly:

```python
current = [0,0,1]
for c in s:
    n = int(c)
    total = sum(current)
    current = [
        total if n == 1 else 0,
        total if n == 2 else 0,
        (total if 3 <= n <= 9 else 0)
        + current[0]
        + (current[1] if 0 <= n <= 6 else 0)
    ]

return sum(current)
```

Python's evaluation order grants that this operation is essentially "atomic", the old array is used within the list construction and then rebound back to the variable `current`.

### Turning the loop into a fold

We now have a loop that takes a state and the next digit, then returns a new state. This is exactly the structure of `reduce()`!

Our initial state is `[0,0,1]`, the input is the digits of `s`, and the reducing function calculates the next three counts. Calling the state `x` and the digit `n`, the transition is :

```python
lambda x, n: [
    sum(x) if n == 1 else 0,
    sum(x) if n == 2 else 0,
    (sum(x) if 3 <= n <= 9 else 0)
    + x[0]
    + (x[1] if 0 <= n <= 6 else 0)
]
```

This already fits into a fold, but we have repeated `sum(x)`. Although the state only contains three entries so this doesn't significantly affect computation, we can calculate its total once by wrapping the list in another lambda:

```python
lambda x, n: (lambda t: [
    t if n == 1 else 0,
    t if n == 2 else 0,
    (t if 3 <= n <= 9 else 0) + x[0] + (x[1] if 0 <= n <= 6 else 0)
])(sum(x))
```

The inner lambda binds `t` to `sum(x)`, just like our original `total` variable. It can still use `x` and `n` from the enclosing lambda.

Finally, `map(int, list(s))` supplies the individual digits as an iterable, `reduce()` carries the state through them, and the outer `sum()` adds up the final three counts :

```python
def numDecodings(self, s):
    return sum(reduce(lambda x, n: (lambda t: [(t if n == 1 else 0), (t if n == 2 else 0), (t if 3 <= n <= 9 else 0) + x[0] + (x[1] if 0 <= n <= 6 else 0)])(sum(x)), map(int, list(s)), [0,0,1]))
```

And we've turned the original DP table into one expression without changing its transitions!

The transition work is linear in the length of `s`, with a constant-size DP state. The exact expression still uses linear auxiliary space for `list(s)` and, in Python 2, the list returned by `map()`. The rolling state itself only needs three counts. In Python 3, `reduce` must be imported from `functools`.

The same three-state representation can be extended to [Decode Ways II](../codes/0639.py). The extra challenge there is counting the possible transitions when the next character is `*` but the progression above provides the context for that extension and it is quite trivial once you understand it.

## Equivalent Code :

```python
def numDecodings(self, s):
    state = [0,0,1]
    for c in s:
        n = int(c)
        total = sum(state)
        state = [
            total if n == 1 else 0,
            total if n == 2 else 0,
            (total if 3 <= n <= 9 else 0)
            + state[0]
            + (state[1] if 0 <= n <= 6 else 0)
        ]
    return sum(state)
```
